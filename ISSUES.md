# Audit findings by subproject

Audit date: 2026-09-29

Scope: the root project, all 23 subprojects described by `documentation/modules.md`, their Java classes and resources, and `samples/`. The review followed the documented initialization, service discovery, request/context, controller/binding/validation, authorization/login, persistence/CRUD, upload/download, view/tag/JavaScript, chart/report generation, runtime compilation, and build/test flows. It combined source/resource tracing with targeted runtime checks and the repository's build scripts.

Severity order inside each subproject is **CRITICAL**, **HIGH**, **MEDIUM**, then **LOW**. Cross-module issues are filed under the subproject that owns the defective implementation and identify affected consumers.

Verification environment: JDK 25.0.2 on Windows/Git Bash. All 21 modules compile, including the 254-source STJS module. The test flow compiles all nine test-bearing modules and executes 330 tests; 329 pass, while one report test remains blocked by a missing StAX2 runtime class.

## `org.nextframework.services`

5. **[HIGH] Providers with the same priority are silently discarded.** `ServiceFactory` stores providers in a `TreeSet` whose comparator returns only the priority difference. Distinct providers with equal priority compare as zero, so only one survives; the documentation's custom-provider example even uses priority 30, which collides with `ServletContextServiceProvider`. Which provider wins depends on discovery/registration order. Iteration over the synchronized set is also performed without external synchronization. Evidence: [`ServiceFactory.java`](org.nextframework.services/src/org/nextframework/service/ServiceFactory.java#L42) and [`README.md`](documentation/org.nextframework.services/README.md#L86). **Fix:** compare priority and a stable unique tiebreaker, or sort a list; snapshot/synchronize iteration.

## `org.nextframework.compilation`

6. **[MEDIUM] Runtime compilation retains every generated bytecode object forever.** `JavaSourceCompiler.compiledFiles` is a static strong-reference list and every output is appended without eviction, defeating the weak classloader design and growing heap for the JVM lifetime. Evidence: [`JavaSourceCompiler.java`](org.nextframework.compilation/src/org/nextframework/compilation/JavaSourceCompiler.java#L52). **Fix:** scope output objects to one compilation/classloader and release them after class definition; use a bounded cache only when required.

## `org.nextframework.context`

7. **[MEDIUM] Global/singleton `SimpleDateFormat` instances are used concurrently.** `Util.dates` exposes one `DateUtils` containing five mutable formatters and `NextFormater` is a singleton with three more. Their parse/format calls are unsynchronized, so web threads can corrupt output or intermittently fail. Evidence: [`Util.java`](org.nextframework.context/src/org/nextframework/util/Util.java#L36), [`DateUtils.java`](org.nextframework.context/src/org/nextframework/util/DateUtils.java#L8), and [`NextFormater.java`](org.nextframework.context/src/org/nextframework/util/NextFormater.java#L31). **Fix:** use immutable `DateTimeFormatter` or a formatter per call.

## `org.nextframework.web`

8. **[HIGH] Request and user context leak across pooled and child threads.** `WebContext` and `Next` use `InheritableThreadLocal`; `WebContextFilter` and `NextFilter` set request state but never remove it in a `finally`, including early returns and exceptions. Completed requests/sessions remain retained and a later task can observe stale identity/request state; child threads inherit it. Evidence: [`WebContext.java`](org.nextframework.web/src/org/nextframework/web/WebContext.java#L9), [`WebContextFilter.java`](org.nextframework.web/src/org/nextframework/web/WebContextFilter.java#L45), [`Next.java`](org.nextframework.context/src/org/nextframework/core/standard/Next.java#L38), and [`NextFilter.java`](org.nextframework.view/src/org/nextframework/core/web/NextFilter.java#L100). **Fix:** use ordinary request `ThreadLocal`s, expose `remove()`, and clear all state in `finally`; explicitly propagate only immutable async context.

9. **[MEDIUM] Each request replaces the application-context wrapper, and root-context deployments crash.** `createRequestContext()` resolves the existing wrapper, then `getRequestContext(request,response)` unconditionally calls `createApplicationContext()` and overwrites it. Separately, `DefaultWebApplicationContext.getApplicationName()` calls `substring(1)` on the valid empty root context path. Evidence: [`NextWeb.java`](org.nextframework.web/src/org/nextframework/core/web/NextWeb.java#L48) and [`DefaultWebApplicationContext.java`](org.nextframework.web/src/org/nextframework/core/web/DefaultWebApplicationContext.java#L52). **Fix:** create/reuse one application wrapper and explicitly handle the root context with a configured/default name.

## `org.nextframework.authorization`

10. **[HIGH] Static role rules do not implement their documented case-insensitive or empty-rule behavior.** Configured values are stored verbatim while only the user's role is lowercased; uppercase examples such as `ADMIN,MANAGER` fail, whitespace is not trimmed, and an empty property becomes a list containing `""`, denying the documented public rule. The shared cache is an unsynchronized `HashMap` mutated by request threads. Evidence: [`AuthorizationManagerImpl.java`](org.nextframework.authorization/src/org/nextframework/authorization/impl/AuthorizationManagerImpl.java#L148) versus [`LEVEL2-STATIC.md`](documentation/org.nextframework.authorization/LEVEL2-STATIC.md#L23) and its [case-insensitive contract](documentation/org.nextframework.authorization/LEVEL2-STATIC.md#L149). **Fix:** trim, discard empty entries, normalize both sides with `Locale.ROOT`, and use a safely published immutable/concurrent cache.

## `org.nextframework.authorization.dashboard`

11. **[HIGH] Login succeeds without rotating the HTTP session identifier.** The authenticated user is stored in the existing session, enabling session fixation. Evidence: [`LoginController.java`](org.nextframework.authorization.dashboard/src/org/nextframework/authorization/LoginController.java#L72). **Fix:** call `changeSessionId()` after authentication or migrate approved attributes into a new session.

12. **[HIGH] The default password verifier performs plain `String.equals`.** Applications that use the shipped controller without overriding `validPassword()` must expose/store a directly comparable password; the comparison is not a password hash verification and is not constant-time. A null persisted password also turns a failed login into a server error. Evidence: [`LoginController.java`](org.nextframework.authorization.dashboard/src/org/nextframework/authorization/LoginController.java#L106). **Fix:** require a `PasswordEncoder` service, ship a modern adaptive-hash implementation, and fail closed if it is absent.

13. **[MEDIUM] Default login-page installation fails in packed WARs and never retries.** `copyLoginPageIfNecessary()` sets `loginChecked=true` before using `ServletContext.getRealPath()` and writing into the deployment. `getRealPath()` may be null for a packed WAR; after the failure, the instance suppresses all retries. Evidence: [`LoginController.java`](org.nextframework.authorization.dashboard/src/org/nextframework/authorization/LoginController.java#L42). **Fix:** resolve the bundled JSP without modifying the deployment, and mark initialization complete only after success.

## `org.nextframework.controller`

14. **[HIGH] Any client can disable server-side annotation and controller validation.** `MultiActionController.suppressValidation()` trusts the request parameter `suppressValidation=true`. This skips `ObjectAnnotationValidator`, controller `validate()`, and configured Spring validators even on save actions, allowing direct requests to bypass required/range/business rules. The hidden field needed for UI reloads is not a security boundary. Evidence: [`MultiActionController.java`](org.nextframework.controller/src/org/nextframework/controller/MultiActionController.java#L917), the documented parameter in [`BINDING.md`](documentation/org.nextframework.controller/BINDING.md#L423), and its normal hidden-field use in [`FormTag.jsp`](org.nextframework.view/src/org/nextframework/view/FormTag.jsp#L7). **Fix:** decide validation suppression server-side from a trusted action type; never accept it as a general request override for state-changing actions.

15. **[MEDIUM] Temporary upload tokens are not bound to a user, session, form, or field.** Binding calls `TempFileTokenSupport.load()` after only checking token syntax. Anyone who obtains a token can attach the file in a different session/form; the intended request cleanup method has no caller, so canceled uploads live until the 15-day expiration. Evidence: [`ServletRequestDataBinderNext.java`](org.nextframework.controller/src/org/nextframework/controller/ServletRequestDataBinderNext.java#L386) and [`TempFileTokenSupport.java`](org.nextframework.controller/src/org/nextframework/controller/TempFileTokenSupport.java#L71). **Fix:** persist/verify ownership and purpose metadata, use short expiry, atomically consume the token, and invoke cleanup on cancellation/failure.

16. **[MEDIUM] Upload handling instantiates a request-selected JVM class.** The client-supplied `fileClassName` reaches `Class.forName()` and a public constructor for any concrete `org.nextframework.types.File` subtype. A caller can select any application subtype and trigger its static initializer/constructor rather than the server determining the expected property type. Evidence: [`UploadFileServlet.java`](org.nextframework.view/src/org/nextframework/view/UploadFileServlet.java#L54) and [`TempFileTokenSupport.java`](org.nextframework.controller/src/org/nextframework/controller/TempFileTokenSupport.java#L46). **Fix:** derive the class from trusted property metadata or map an opaque allowlisted identifier.

17. **[MEDIUM] Classpath JSP resolution assumes an exploded, writable WAR and leaks streams.** `NextCompositeViewResolver` copies classpath JSPs into `getRealPath("/WEB-INF/classes")`; packed deployments may return null and deployments may be read-only. Input/probe streams are not reliably closed. Evidence: [`NextCompositeViewResolver.java`](org.nextframework.controller/src/org/nextframework/controller/NextCompositeViewResolver.java#L50). **Fix:** use a classpath-capable view mechanism or application-owned temporary storage and try-with-resources.

## `org.nextframework.dao`

18. **[HIGH] Request-bound CRUD sorting accepts an arbitrary HQL fragment and invalid pagination values.** `ListViewFilter` stores any `orderBy`, `pageSize`, and page index; `ResultListImpl` appends the sort expression to HQL. `pageSize=0` divides by zero, negative/huge values reach pagination, and crafted expressions alter query parsing. Evidence: [`ListViewFilter.java`](org.nextframework.dao/src/org/nextframework/controller/crud/ListViewFilter.java#L88), its request-bound use in [`AbstractCrudController.java`](org.nextframework.controller/src/org/nextframework/controller/crud/AbstractCrudController.java#L57), and [`ResultListImpl.java`](org.nextframework.dao/src/org/nextframework/persistence/ResultListImpl.java#L49). **Fix:** map client sort keys to server-approved paths and enforce page bounds.

19. **[MEDIUM] `FileDAO` can silently return partial/corrupt content and overflow for large files.** It casts `file.length()` to `int`, allocates once, and performs one `read(bytes)` even though reads need not fill the buffer. Files over 2 GiB overflow; read/write streams are not protected on exceptional paths. Evidence: [`FileDAO.java`](org.nextframework.dao/src/org/nextframework/persistence/FileDAO.java#L78). **Fix:** enforce an explicit size limit, loop until EOF (or use a safe Files API), use try-with-resources, and write atomically.

## `org.nextframework.types`

20. **[MEDIUM] Six value types violate `equals`/`hashCode` for null-valued instances.** `Cpf`, `Cnpj`, `Cep`, `InscricaoEstadual`, `Phone`, and `PhoneBrazil` consider two null-valued instances equal but use identity `super.hashCode()`. Equal values then have different hashes, breaking hashed collections and persistence caches. Evidence: [`Cpf.java`](org.nextframework.types/src/org/nextframework/types/Cpf.java#L150), [`Cnpj.java`](org.nextframework.types/src/org/nextframework/types/Cnpj.java#L105), [`Cep.java`](org.nextframework.types/src/org/nextframework/types/Cep.java#L68), [`InscricaoEstadual.java`](org.nextframework.types/src/org/nextframework/types/InscricaoEstadual.java#L68), [`Phone.java`](org.nextframework.types/src/org/nextframework/types/Phone.java#L72), and [`PhoneBrazil.java`](org.nextframework.types/src/org/nextframework/types/PhoneBrazil.java#L53). Several matching Hibernate `UserType.hashCode()` methods also dereference null. **Fix:** return a stable hash (normally zero) for null and make every `UserType` null-safe.

21. **[MEDIUM] `MoneyUserType.equals()` throws on a value-to-null transition.** When `x` is non-null it unconditionally calls `x.compareTo(y)`; a null `y` causes `Money.compareTo()` to throw during Hibernate dirty checking instead of returning false. Evidence: [`MoneyUserType.java`](org.nextframework.types/src/org/nextframework/types/hibernate/MoneyUserType.java#L23). **Fix:** handle identity/either-null before comparison and test both null transitions.

22. **[MEDIUM] CPF and CNPJ validation accepts repeated-digit identifiers documented as invalid.** Runtime verification on the audited code returns true for `Cpf.cpfValido("11111111111")` and `Cnpj.cnpjValido("00000000000000")`; the CPF documentation explicitly uses the repeated-one value as invalid. Evidence: [`Cpf.java`](org.nextframework.types/src/org/nextframework/types/Cpf.java#L65), [`Cnpj.java`](org.nextframework.types/src/org/nextframework/types/Cnpj.java#L69), and [`README.md`](documentation/org.nextframework.types/README.md#L79). **Fix:** reject all-equal digit sequences before checksum evaluation and add known-valid/known-invalid tables.

## `org.nextframework.validation`

23. **[HIGH] Client-validation JavaScript is generated by concatenating unescaped names and messages.** Form names, field names, translated validation messages, and validator functions are inserted into quoted JavaScript. Quotes, backslashes, newlines, or `</script>` can break the script or execute markup when message/display-name content is externally managed. The generated wrapper catches JavaScript errors and returns true, silently disabling client validation. Evidence: [`JavascriptValidationFunctionBuilder.java`](org.nextframework.validation/src/org/nextframework/validation/validators/JavascriptValidationFunctionBuilder.java#L52). **Fix:** serialize data with a context-safe JSON encoder, keep executable code static, and fail visibly rather than approving on script errors.

## `org.nextframework.jsbuilder`

24. **[HIGH] The JavaScript string encoder does not make values safe inside inline `<script>` elements.** It escapes backslash, double quote, and newline, but not `<`, `</script>`, carriage return, or Unicode line separators. Database/report strings embedded through charts or other builders can terminate the script element and inject HTML/JavaScript. Evidence: [`JSBuilderUtils.java`](org.nextframework.jsbuilder/src/org/nextframework/view/js/JSBuilderUtils.java#L23) and inline use by [`HtmlReportBuilderImpl.java`](org.nextframework.report/jasper-html-src/org/nextframework/report/renderer/html/builder/HtmlReportBuilderImpl.java#L416). **Fix:** use a JSON serializer configured for HTML-safe inline output, or place JSON in a non-executable data block and load it separately.

## `org.nextframework.summary`

25. **[MEDIUM] The dynamic-summary cache has strong keys and weak values, so keys accumulate forever.** Every distinct `DynamicSummary` is retained by a static `HashMap`; clearing the weak generated-class value does not release the key. The get/create/put sequence is also not atomic despite a synchronized wrapper. Evidence: [`DynamicSummaryImpl.java`](org.nextframework.summary/src/org/nextframework/summary/dynamic/DynamicSummaryImpl.java#L24). **Fix:** use bounded/weak-key caching and atomic computation, or scope generated summaries to an application context.

## `org.nextframework.view`

26. **[HIGH] Core JSP tag templates render model values and attributes without HTML/JavaScript escaping.** Text, textarea, hidden, select, link, form, mask, and other templates write `${tag.valueToString}`, descriptions, IDs, patterns, URLs, and dynamic attributes directly into HTML attributes, element bodies, or scripts. A persisted value containing quotes/markup becomes stored XSS. Evidence: [`InputTag-text.jsp`](org.nextframework.view/src/org/nextframework/view/InputTag-text.jsp#L3), [`InputTag-text_area.jsp`](org.nextframework.view/src/org/nextframework/view/InputTag-text_area.jsp#L2), [`InputTag-select_one.jsp`](org.nextframework.view/src/org/nextframework/view/InputTag-select_one.jsp#L2), and [`FormTag.jsp`](org.nextframework.view/src/org/nextframework/view/FormTag.jsp#L5). **Fix:** introduce context-specific HTML attribute/text/JavaScript escaping and make raw HTML an explicit opt-in type only.

27. **[HIGH] Suggestion labels are inserted with `innerHTML`, providing a direct stored-XSS sink.** Suggest labels come from bean descriptions/database values, are serialized to `_t`, and the browser assigns `_t` to `li.innerHTML`. The surrounding inline JSON is also vulnerable to a `</script>` terminator. Evidence: [`SuggestProviderTag.java`](org.nextframework.view/src/org/nextframework/view/SuggestProviderTag.java#L48), generated source [`NextSuggest.java`](org.nextframework.stjs/js-builder/org/nextframework/resource/NextSuggest.java#L316), and deployed [`NextSuggest.js`](org.nextframework.view/resources/org/nextframework/resource/NextSuggest.js#L229). **Fix:** use `textContent` and deliver data through an HTML-safe JSON transport.

28. **[HIGH] Password inputs send the persisted password/hash back to the browser.** The template comment says the value is withheld, but the actual tag renders `value="${tag.value}"`. Any edit form using `@Password` exposes the stored secret/hash in HTML/DOM and resubmits it. Evidence: [`InputTag-password.jsp`](org.nextframework.view/src/org/nextframework/view/InputTag-password.jsp#L2) and type selection in [`InputTagHelper.java`](org.nextframework.view/src/org/nextframework/view/InputTagHelper.java#L125). **Fix:** always render password inputs empty and preserve/change the stored value through explicit server-side logic.

29. **[HIGH] The globally mapped upload servlet has no size limit and buffers each part fully in heap.** Bare `@MultipartConfig` leaves request/file size unlimited; `readBytes()` makes a full memory copy before serialized disk storage, and the servlet itself performs no authentication/authorization check. Large/repeated requests can exhaust heap, disk, or threads. Evidence: [`web-fragment.xml`](org.nextframework.view/resources/META-INF/web-fragment.xml#L82) and [`UploadFileServlet.java`](org.nextframework.view/src/org/nextframework/view/UploadFileServlet.java#L39). **Fix:** require authorization, enforce proxy/container/servlet quotas, stream to bounded storage, and rate-limit.

30. **[MEDIUM] Static assets create sessions for anonymous visitors.** `ResourceProvider` calls `request.getSession().getServletContext()` in both delivery and last-modified flows, creating a session/cookie for CSS/JS/image requests. Evidence: [`ResourceProvider.java`](org.nextframework.view/src/org/nextframework/view/ResourceProvider.java#L87). **Fix:** use `request.getServletContext()` and application initialization state.

31. **[MEDIUM] `IncludeTag` is an unrestricted server-side HTTP fetch with no timeouts.** A request/content-derived tag URL becomes SSRF, while even a developer-authored slow endpoint can hold a servlet thread indefinitely. Evidence: [`IncludeTag.java`](org.nextframework.view/src/org/nextframework/view/IncludeTag.java#L48). **Fix:** use request dispatch for local includes; if remote fetch is necessary, allowlist destinations and enforce connect/read/size limits.

32. **[MEDIUM] Tag-template extraction assumes an exploded writable deployment and its caches are unsafe/disabled.** `BaseTagTemplateManager` uses `getRealPath()`, opens JARs from the deployment, and writes JSPs into `/WEB-INF/classes`; this fails for packed/read-only WARs. Static `HashSet`/`HashMap` caches are accessed outside synchronization, copied templates are not marked cached, and `getTextFromTemplate()` explicitly resets every cache hit to null. Evidence: [`BaseTagTemplateManager.java`](org.nextframework.view/src/org/nextframework/view/BaseTagTemplateManager.java#L29). **Fix:** package/resolve templates without deployment writes and use correctly synchronized immutable/concurrent caches.

33. **[MEDIUM] The OGNL expression cache is an unbounded, publicly mutable, racy `HashMap`.** Reads occur outside the synchronized write block; concurrent parsing can observe unsafe map state, and distinct expressions are never evicted. Evidence: [`OgnlExpressionParser.java`](org.nextframework.view/src/org/nextframework/view/OgnlExpressionParser.java#L19). **Fix:** make the cache private and bounded, using `ConcurrentHashMap.computeIfAbsent`.

## `org.nextframework.report`

34. **[HIGH] HTML report rendering outputs report/database values as raw HTML.** `createHtmlTextTag()` assigns Jasper text/converted report labels to `HtmlTag.innerHTML`; `HtmlTag` also emits attributes without escaping. Stored report data containing markup executes when the HTML report is viewed. Exception messages and report names also reach raw HTML/JavaScript sinks. Evidence: [`HtmlReportBuilderImpl.java`](org.nextframework.report/jasper-html-src/org/nextframework/report/renderer/html/builder/HtmlReportBuilderImpl.java#L309) and [`HtmlTag.java`](org.nextframework.report/jasper-html-src/org/nextframework/report/renderer/html/design/HtmlTag.java#L105). **Fix:** HTML-escape text and attributes by default and model intentional markup as a separate trusted type.

## `org.nextframework.report.generator`

35. **[CRITICAL] Report XML values are inserted into generated Java source, enabling server-side code execution.** The title is concatenated into a Java string literal and `SourceCodeBlock.call()` repeats the defect for labels/patterns. The generated source is compiled and loaded; `saveReport()` accepts request XML. A report author can close a literal and inject Java executed with server privileges. Evidence: [`ReportBuilderSourceGenerator.java`](org.nextframework.report.generator/src/org/nextframework/report/generator/source/ReportBuilderSourceGenerator.java#L180), [`SourceCodeBlock.java`](org.nextframework.compilation/src/org/nextframework/compilation/SourceCodeBlock.java#L70), [`ReportGeneratorContext.java`](org.nextframework.report.generator/src/org/nextframework/report/generator/ReportGeneratorContext.java#L36), and [`ReportDesignController.java`](org.nextframework.report.generator/src/org/nextframework/report/generator/mvc/ReportDesignController.java#L198). **Fix:** do not embed untrusted text in source; pass it as runtime data. Until redesigned, apply a complete Java-literal encoder and strict allowlists, and restrict report editing.

36. **[HIGH] Report XML parsing permits XXE and DTD/entity expansion.** A default `DocumentBuilderFactory` parses request/persisted XML without secure-processing or external entity/DTD restrictions. Evidence: [`ReportReader.java`](org.nextframework.report.generator/src/org/nextframework/report/generator/ReportReader.java#L47) and [`ReportDesignController.java`](org.nextframework.report.generator/src/org/nextframework/report/generator/mvc/ReportDesignController.java#L210). **Fix:** disallow DOCTYPE, disable external entities/DTDs/schema access, enable secure processing, and install a rejecting resolver.

37. **[HIGH] Raw XML report mode can query arbitrary mapped entities and bypass the designer's entity/property allowlist.** The visual designer selects `@ReportEntity` classes, but XML supplies any `fromClass`; `ReportReader` delegates it to `Class.forName()`. `validateRequiredFields()` returns immediately when `selectedType` is null (XML-edit mode), so an authorized report author can select other mapped entities/relationships and retrieve data outside the intended report surface. Evidence: [`HibernateDataSourceProvider.java`](org.nextframework.report.generator/src/org/nextframework/report/generator/datasource/HibernateDataSourceProvider.java#L44), available-type discovery in [`ReportDesignControllerUtil.java`](org.nextframework.report.generator/src/org/nextframework/report/generator/mvc/ReportDesignControllerUtil.java#L63), and the bypass in [`ReportDesignController.java`](org.nextframework.report.generator/src/org/nextframework/report/generator/mvc/ReportDesignController.java#L226). **Fix:** resolve types from a server-side allowlist and validate every property/filter against the selected report policy in both visual and raw XML modes.

38. **[HIGH] The report designer writes titles/labels to `innerHTML` and builds XML without escaping.** Saved markup executes in the designer, while `'`, `&`, and `<` corrupt the generated XML and feed the server-side parser/compiler sinks. Evidence: [`ReportDesigner.java`](org.nextframework.report.generator/js-builder/org/nextframework/report/generator/mvc/resource/ReportDesigner.java#L543) and [`ReportPropertyConfigUtils.java`](org.nextframework.report.generator/js-builder/org/nextframework/report/generator/mvc/resource/ReportPropertyConfigUtils.java#L162). **Fix:** use `textContent`, build XML with an XML API, and escape every text/attribute value.

39. **[MEDIUM] `limitResults` is not actually enforced.** The Hibernate provider always fetches pages of 500, appends the complete page, and checks the limit only afterward. A limit from 1-499 still returns up to 500; 501-999 can return up to 1,000, increasing exposure and memory usage. Evidence: [`HibernateDataSourceProvider.java`](org.nextframework.report.generator/src/org/nextframework/report/generator/datasource/HibernateDataSourceProvider.java#L86). **Fix:** cap page size by remaining allowance and trim/stop exactly at the configured limit.

40. **[MEDIUM] The generated-report class cache retains strong report keys forever.** `ReportGeneratorContext` uses a static `HashMap<ReportElement, WeakReference<Class<...>>>`; weak values do not release the strong keys, and stale entries are never removed. Compound lookup/creation is also non-atomic. Evidence: [`ReportGeneratorContext.java`](org.nextframework.report.generator/src/org/nextframework/report/generator/ReportGeneratorContext.java#L16). **Fix:** use bounded or weak-key application-scoped caching with atomic creation.

## Root project / cross-project metadata

41. **[MEDIUM] Jakarta/Servlet 6.1 migration metadata is inconsistent.** The documentation declares Jakarta and Java 25, but multiple `.iml` files still reference `javax.servlet-api-3.1.0.jar`/legacy JSP/EL artifacts, while sample/web-fragment descriptors use the old Java EE Servlet 3.0 namespace. IDE compilation and descriptor behavior therefore differ from the Ivy/documented platform. Evidence: [`org.nextframework.web.iml`](org.nextframework.web/org.nextframework.web.iml), [`org.nextframework.report.generator.iml`](org.nextframework.report.generator/org.nextframework.report.generator.iml), [`sample/web.xml`](org.nextframework/sample/web.xml), and [`web-fragment.xml`](org.nextframework.web/resources/META-INF/web-fragment.xml). **Fix:** align IDE dependencies and descriptors with the exact Jakarta coordinates/schema versions used by the build.

## `samples/showcase_app`

42. **[HIGH] The sample user-edit flow exposes and trusts bcrypt-looking client input.** The framework password template sends the existing hash to the browser. On save, `UserCrudController` treats any submitted value beginning with `$2a$` as already hashed, so a caller can submit a chosen bcrypt hash instead of a password and have it stored verbatim. This is a credential takeover primitive for any user the caller may edit and teaches an unsafe pattern. Evidence: [`userForm.jsp`](samples/showcase_app/WebContent/WEB-INF/jsp/app/crud/userForm.jsp#L9), [`User.java`](samples/showcase_app/src/org/erplite/entity/User.java#L27), and [`UserCrudController.java`](samples/showcase_app/src/org/erplite/controller/UserCrudController.java#L31). **Fix:** never render the stored hash, load the existing hash only server-side when the submitted password is blank, and always hash any nonblank client value regardless of prefix.

## Subprojects with no additional confirmed issue in this pass

The class/resource flows in `org.nextframework`, `org.nextframework.beans`, `org.nextframework.core`, `org.nextframework.chart`, `org.nextframework.legacy`, `org.nextframework.persistence`, and `org.nextframework.stjs` were reviewed but produced no separate source-confirmed finding beyond the cross-module/build issues above. `org.nextframework.stjs` is specifically affected by issue 5. This statement is an audit result, not a guarantee that those modules are defect-free.
